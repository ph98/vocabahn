# AI-First Re-Plan

Outcome of the 2026-07-05 design grilling. Vocabulary: see `/CONTEXT.md`.
Decisions of record: ADR 0001 (Knowledge Model as hub), ADR 0002
(deterministic planner, LLM surface).

## Vision

Vocabahn's differentiator over generic AI tutors is its per-user, per-word
knowledge ledger with a forgetting forecast. Every AI capability is built to
exploit it: content generated to the learner's exact vocabulary, review that
happens implicitly through use, and a plan that continuously adapts. Delivery
is **evolution of the existing codebase, not a rewrite** — the inversion is
additive.

## Decision summary

1. **Architecture inversion (ADR 0001).** Knowledge Model becomes the hub;
   Experiences (cards, stories, drills, later conversation) emit Evidence
   Events; FSRS is one consumer. Existing review history is back-filled into
   the ledger as `card-self-grade` evidence so the ledger is complete ground
   truth from day one.
2. **Evidence Policy.** Raw events are immutable; a single policy module
   aggregates per item per session into at most one FSRS update. Failure
   dominates within a session. Weak (passive) evidence can maintain a schedule
   but never graduate a word to Known; graduation requires production or
   unprompted recall.
3. **v1 Experience roster.** Micro-Story (+ Micro-Check), Production Drill,
   and classic cards demoted to residual review (self-grades routed through
   the policy like everything else). Conversation and grammar Error Profile
   are v2; the architecture guarantees they plug in without rework.
4. **Evidence from reading.** Tap-to-Reveal = negative evidence only;
   positive evidence comes solely from the Micro-Check. Pure reading never
   feeds the scheduler.
5. **Production Drill.** Typed only, two forms (DE↔EN translation; use the
   word in a sentence). LLM verdict scoped to the target word
   `{correct|partial|wrong}`; whole-sentence coaching feedback is shown but
   never scheduled.
6. **Cold start.** Declared CEFR + frequency priors (exists) plus an adaptive
   Calibration Quiz seed an **Assumed Known** state — distinct from evidenced
   Known, usable by generators, self-healing via story taps. Bulk known-word
   marking is prior-setting, not fake evidence.
7. **Token↔item binding.** The story generator self-annotates Target Word
   spans with lemmas (validated against the text). Background-word taps use
   the existing dictionary form-of resolution. A standalone lemmatizer is
   deferred until text import (v2).
8. **Planner (ADR 0002).** Deterministic pure-function core (due load, time
   budget, mix weights → session composition). LLM at the edges: goal
   parsing, plan explanation, plan negotiation, story topic selection.
9. **LLM serving.** One provider-agnostic gateway module (enrichment folds
   in). Stories pre-generated by BullMQ after each session using tomorrow's
   plan; SSE-skeleton on-demand fallback. Small fast model for grading and
   explanations; top-tier model for stories.
10. **UI surface.** No chat tab in v1. Dashboard leads with a "Today's Plan"
    card: composed session, one-line LLM explanation, negotiation via quick
    chips + free text. This surface grows into the v2 tutor. Onboarding
    collects: CEFR level, free-text Goal, interest areas, Calibration Quiz.

## Phasing

Each v1 deliverable has a full PRD: [Evidence Ledger](./prd/evidence-ledger.md)
(A), [Production Drill](./prd/production-drill.md) and
[Micro-Story](./prd/micro-story.md) (B), [Planner](./prd/planner.md) (C).

### Phase A — Foundation (enables everything)
- Evidence ledger schema + Evidence Policy module (unit-tested rules from
  decision 2).
- Backfill migration of existing FSRS review history.
- Reroute the existing card-review write path through the policy.
- LLM gateway; migrate enrichment calls into it.

### Phase B — Experiences
- Production Drill: grading endpoint (structured verdict) + drill UI.
- Micro-Story: generation with self-annotated Target Word spans +
  Micro-Check questions; span validation; pre-generation BullMQ job;
  reader UI with Tap-to-Reveal; Micro-Check UI.

### Phase C — Planner & surface
- Goal / Learning Plan entities; planner core (pure function).
- Goal parsing, plan explanation, plan negotiation via gateway.
- "Today's Plan" dashboard card with chips + free-text negotiation.
- Onboarding additions: goal, interests, Calibration Quiz.

### Phase D — v2 (post-spine)
- Conversation experience (vocab-constrained dialogue, implicit review).
- Grammar Concepts as Knowledge Items + Error Profile mining.
- Text import with standalone lemmatizer.
- MCP server (`docs/mcp_integration.md`) — exposes the ledger and planner
  to external AI clients.

## Open leaves (deliberately unresolved)
- Micro-Check question formats (MC vs one-line cloze mix).
- Calibration Quiz sampling algorithm and spot-check honesty mechanism.
- Fate of decks/courses under the Planner (likely become Plan inputs/tracks).
- Evidence-strength weighting constants — tune once real data exists.
